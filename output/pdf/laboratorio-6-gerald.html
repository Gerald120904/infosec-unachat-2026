02 · Arquitectura

Aplicación e instrumentación

UNA Chat utiliza Express para servir la interfaz y Socket.IO para recibir el evento Evento-Mensaje-Server y difundir el mensaje a los clientes conectados.

Cambios implementados

  • Socket.IO usa la ruta /api/socket-io/socket.io en cliente, servidor y pruebas, con transporte WebSocket y reconexión.
  • OpenTelemetry se inicializa antes de Express/HTTP; se agregaron spans de mensajes y métricas HTTP/chat.
  • Pino produce eventos estructurados con trace_id y span_id, sin registrar el texto del chat.
  • Sentry Node SDK solo inicia en Vercel y requiere SENTRY_DSN; se desactiva el envío de PII y se filtran cookies, cabeceras y query strings.
  • La ruta HTTP de laboratorio /__lab/message solo está disponible fuera de Vercel y reutiliza el validador real.
  • Docker publica el servicio solamente en 127.0.0.1:3000.
Privacidad de telemetría: la configuración previene exportar desde Vercel. La entrega OTLP real desde Docker todavía requiere validar credenciales localmente en el archivo ignorado .env.

Protocolo Socket.IO verificado

El cliente envía una cadena JSON con nombre, mensaje y color a Evento-Mensaje-Server. El servidor valida el contenido y lo difunde a los clientes mediante el evento de respuesta del chat. Las pruebas validan recepción en ambos clientes.
