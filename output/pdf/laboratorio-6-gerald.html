Parte 1 · arquitectura

Aplicación y protocolo

UNA Chat usa Express para servir index.html y Socket.IO sobre el servidor HTTP. Los clientes envían el evento Evento-Mensaje-Server con una cadena JSON que contiene nombre, mensaje y color. El servidor valida y escapa el contenido antes de emitir la respuesta.

Recorrido observado

Browser ── HTTP GET / ──> Express
Browser ══ Engine.IO WebSocket ══> Socket.IO
Client ── Evento-Mensaje-Server(JSON string) ──> validateMessage
Server ── Evento-Mensaje-Server(validated JSON) ──> connected clients
Adaptación de cliente: el navegador usa transporte WebSocket, reconexión automática, intervalos crecientes acotados y timeout de conexión de 10 segundos.

Modificaciones principales

  • server.js: orden de instrumentación, métricas HTTP/chat, spans y endpoint HTTP exclusivo del laboratorio local.
  • telemetry.js y logger.js: SDK OpenTelemetry y Pino con IDs de traza/span.
  • index.html: WebSocket y reconexión configurados.
  • Dockerfile, Compose y Artillery: ejecución local reproducible.
  • vercel.json: preparación de entrada Express y archivo estático.

Parte 2 · OpenTelemetry

Señales locales instrumentadas

El bootstrap telemetry.js se carga antes de Express y HTTP. La auto-instrumentación captura HTTP; spans manuales envuelven el procesamiento de cada mensaje Socket.IO y del adaptador HTTP de laboratorio. Pino lee el span activo y añade trace_id y span_id.

SeñalInstrumentaciónVerificación local
LogsPino JSON + ambiente + trace/span IDsLogs reales del contenedor archivados
MétricasContadores de solicitudes, errores y mensajes; histogramas de duraciónInstrumentación en proceso; no exportada a nube aún
TrazasAuto-instrumentación HTTP + spans chat.process_messageIDs correlacionados en logs; exportación remota no configurada
Grafana Cloud: el SDK permite OTLP/HTTP para los tres tipos de señal, pero no hay aún endpoint/credencial Grafana cargados. Por tanto, no se presentan capturas ni se afirma recepción remota. Para continuar se requiere completar autenticación en el navegador y configurar las variables secretas OTLP directamente en la máquina.

Privacidad y aislamiento

  • Exportadores apagados si faltan endpoint y headers.
  • Sin exportación desde Vercel o NODE_ENV=test.
  • El contenedor Compose solo exportará a Grafana si sus variables OTLP se completan localmente.

Preparación de Vercel

El repositorio tiene un archivo vercel.json orientado al entrypoint Express y al archivo HTML. El código mantiene el servidor HTTP/Socket.IO para ofrecer WebSockets y solo llama listen() cuando se ejecuta como proceso local. La ruta HTTP de Artillery está excluida si VERCEL=1.
